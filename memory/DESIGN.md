# 记忆系统设计

## 核心原则

### 用户隔离

每个用户的分析记录严格隔离：
- **不同用户的分析记录不跨引用**
- **回溯历史前先确认用户身份**
- **不预设与用户的过往合作**
- **不将A用户的分析内容透露给B用户**

### 存储结构

```
memory/
├── users/                  # 用户画像
│   ├── README.md           # 用户系统说明
│   ├── roster.md           # 团队花名册
│   └── [username].md       # 个人画像文件
├── analyses/               # 分析档案
│   └── YYYY-MM-DD_HH-MM_简述.md
├── schema/                 # 存储结构定义
│   ├── user-profile.md     # 用户画像结构
    └── analysis-record.md  # 分析档案结构
└── examples/               # 示例文件
```

## 用户画像

每个用户有独立的画像文件，包含：

```markdown
# [用户姓名]

## 基本信息
- **用户ID**: xxx
- **角色**: [在团队中的角色]
- **首次分析**: [日期] [录音主题]

## 分析历史
| 日期 | 录音主题 | 核心发现 |
|------|---------|---------|
| ... | ... | ... |

## 行为模式
- **发言风格**: [直接/含蓄/发散/...]
- **决策倾向**: [激进/保守/观望/...]
- **认知水平**: [对相关领域的理解深度]

## 关键判断演变
| 日期 | 判断 | 变化原因 |
|------|------|---------|
| ... | ... | ... |

## 沉默信号
- 在哪些话题上沉默
- 回避了哪些问题
```

---

## 分析档案

每次分析生成独立档案：

```markdown
# [日期] · [会议主题] · 分析档案

## 基本信息
- **时间**: YYYY-MM-DD HH:MM
- **参与者**: [列表]
- **采用方法**: #XXX + #XXX

## 核心发现
[核心判断速览]

## 行动项
| 行动项 | 责任人 | 时限 | 状态 |
|--------|--------|------|------|
| ... | ... | ... | 待执行/已完成 |

## 跨录音追踪
[如有历史分析，包含纵向追踪对比表]
```

---

## 跨录音关联

当分析同一项目或同一人物的多次录音时：

1. **搜索历史分析**：在 `memory/analyses/` 中搜索同项目/同人物的历史记录
2. **读取用户画像**：获取人物基本信息和历史立场
3. **输出纵向追踪对比表**：
   - 核心议题演变（推进/停滞/倒退/新增）
   - 人物立场追踪（强化/软化/漂移）
   - 行动项兑现（完成/部分/未做/无提及）
   - 新出现的矛盾（新增/旧有）

---

## 自动学习

分析后如有用户纠正，记录纠正内容：
- **纠正类型**：说话人纠正 / 方法纠正 / 深度纠正 / 遗漏信号
- **纠正内容**：具体纠正了什么
- **适用场景**：下次分析时如何应用这个纠正
