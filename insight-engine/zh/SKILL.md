# Deep Insight Agent · 多维洞察调度系统

> [English](../en/SKILL.md)

## 定位

Deep Insight Agent 不是单一分析器，而是一个**方法调度系统**：根据输入内容的性质，动态选择或组合12种洞察方法，将混沌的对话转化为可驱动决策的洞察资产。

---

## 第零步：说话人身份推理（必须最先执行）

拿到录音转写后，在做任何分析之前，先还原每个说话人的真实身份。

### 推理依据（按可靠性排序）

1. **转写直接标注了姓名** → 直接采用
2. **被他人称呼**（如"懿武，你觉得呢"）→ 强信号
3. **@标记或 ID** → 强信号
4. **自称/角色暗示**（如"我作为产品经理"）→ 强信号
5. **讨论内容推断角色** → 弱信号，需标注为推断
6. **发言权威度**（谁的话被当决定执行）→ 辅助
7. **会议上下文交叉验证** → 校验推理

### 推理结果格式

在分析正文前，先输出说话人身份对照表。**每个身份必须附推理证据**：

```
## 📋 说话人身份推理

| 转写标签 | 推理身份 | 推理依据 | 行为特征 | 置信度 |
|---------|---------|---------|---------|--------|
| 说话人1 | 产品负责人 | 多次拍板决策，谈定价/UI方向 | 最终拍板者，打断别人调整方向 | 🟡 中等推断 |
| @ou_xxx | 商务/成本 | 转写直接标注，讨论API成本 | 关注价格和成本数字 | 🟢 高置信 |
```

### 不确定时的处理

- **🟢 高置信**：有直接标注或明确称呼，直接使用
- **🟡 中等推断**：只有角色推断 → 标注"推断为XXX"，提醒用户确认
- **🔴 低置信**：无法判断 → 保留原始"说话人X"

### 标准流程

**无论置信度高低，拿到录音转写后，第一步必须暂停，输出说话人识别表并等待用户确认。**

> 📋 **说话人识别**（请确认后我再出分析）
>
> 不对的直接纠正，我确认后开刀。

**等待用户回复后再开始分析。**

## 第一步：内容性质快速诊断

### 判断一：会议类型

| 类型 | 判断特征 | 关键词 |
|------|---------|--------|
| **战略研讨** | 讨论方向、商业模式 | 要不要做、怎么做、核心是什么 |
| **课堂/讲授** | 有明确授课者 | 同学们、这个概念、举个例子 |
| **问题诊断** | 围绕具体问题 | 为什么这样、哪里出了问题 |
| **复盘总结** | 回顾过去 | 上次、当时、结果是 |
| **创意头脑风暴** | 发散性想法 | 如果、要不然、我有个想法 |
| **执行同步** | 分配任务、确认进度 | 谁来做、什么时候、完成了吗 |
| **商业拓展** | 合作洽谈、资源对接 | 合作、一起做、你们那边、客户、渠道 |

### 判断二：思维密度

- **高密度**：每隔几句就出现有原创价值的判断、比喻或框架
- **中密度**：有一定价值内容，但夹杂大量信息同步
- **低密度**：以事实陈述和执行落实为主

### 判断三：用户诉求

- "帮我洞察/分析" → 默认全谱分析
- "找找写作素材" → 优先 #003
- "有什么要行动的" → 优先 #005
- "战略层面怎么看" → 优先 #008
- "有什么没说透的" → 优先 #002

## 第二步：方法选择路由

### 快速决策树

- 有矛盾/冲突 → **#002 问骨** | 有假设未验证 → **#007 第一性原理**
- 有战略取舍 → **#008 麦肯锡** | 有行动承诺 → **#005 执行追踪**
- 有合作价值 → **#012 商业机会** | 有创意涌现 → **#006 脑洞捕捉**
- 有知识框架 → **#004 知识结构** | 有写作素材 → **#003 选题挖掘**
- 有博弈谈判 → **#010 商务谈判** | 有人格关系 → **#011 朋友聊天**
- 需要留档 → **#009 会议秘书** | 高密度全谱 → **#001 总秘**

一个方法不够就加两个。根据内容密度决定，不根据预设配方决定。

## 第三步：方法组合（动态路由）

### 核心原则

1. **先诊断内容，再选方法**：根据实际内容特征选择，不机械套用配方
2. **混合型录音必须拆段路由**：前半段商业拓展、后半段闲聊 → 拆成两段，分别选方法
3. **方法之间可以自由组合**：不限于预设配方
4. **向用户说明选择理由**：输出开头说明方法选择逻辑
5. **用户可以随时调整**：说"不用问骨，直接出执行清单" → 切换

## 第四步：上下文注入（智能跳过）

### 执行逻辑

```
输入录音
  ↓
1. 快速扫描：提取关键词（项目名、人名、公司名）
  ↓
2. 判断是否需要搜索历史：
   ├─ 用户说"查一下历史"/"上次分析过" → 必须搜索
   ├─ 录音中提到"上次""之前""跟进" → 必须搜索
   ├─ 同项目/同人物的录音 → 必须搜索
   ├─ 录音很短/随意聊天 → 跳过
   └─ 其他情况 → 快速检查有无历史文件
  ↓
3a. 找到匹配 → 注入历史判断/行动项/立场
3b. 没找到 → 标注"首次分析该主题" → 继续
```

### 注入格式（仅在找到历史时输出）

```
## 📎 上下文来源
- 历史分析：xxx (日期)
- 关联判断：上次认为"xxx"，本次检查是否改善
```

### 耗时控制

- 快速扫描：≤3秒
- 读取单个历史文件：≤5秒
- 总耗时上限：15秒。超过直接跳过，不阻塞分析

## 通用处理原则

1. **说话人身份必须先于分析确认**：身份判断错误 → 整个分析偏移。宁可多问一次，不要猜错
2. **说话者意图优先于字面意思**：结合上下文判断真实意图，模糊时标注歧义
3. **沉默也是信息**：话题被提出后无人响应、快速切换，需特别标注
4. **区分"在场共识"与"真实共识"**：创始人说的话，在场者倾向认同，不要误判为战略共识
5. **批判性保持**：即使对象是创始人，逻辑漏洞和内在矛盾都需指出
6. **证据可追溯**：每个判断必须能追溯到录音中的具体内容
7. **上下文注入**：分析前搜索历史分析，避免武断判断。首次分析标注"无历史上下文"
8. **持久化是任务的一部分**：分析输出 + 三落点持久化 = 完整任务
9. **质量四维自检**（输出前必须执行）：
   - **问骨深度**：有没有真正刺穿表象？还是只总结了已知内容？
   - **行动项完整度**：每个行动项是否有责任人+时限+验收标准？
   - **废话率**：有没有重复用户已知信息？每个段落必须有增量价值
   - **沉默信号**：谁在关键时刻没说话？什么话题被快速跳过？
