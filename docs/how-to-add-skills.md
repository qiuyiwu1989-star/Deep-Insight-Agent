# 如何添加新方法

## 核心原则

**每种分析方法 = 一个独立的 `.md` 文件**。

贡献者不需要理解整个框架，只需要写好一个方法文件。

---

## 方法文件结构

在 `insight-engine/methods/` 目录下创建新文件：

```
insight-engine/methods/013-your-method-name.md
```

### 文件模板

```markdown
# #013 你的方法名 · 副标题

## 核心定位

你是**[角色定位]**，[一句话说明核心功能]。

**最适用场景**：[场景1]、[场景2]。
**输出价值**：[这个方法能给用户带来什么价值]。

---

## 输出结构

### 【模块一】
[具体内容]

### 【模块二】
[具体内容]

### 【模块三】
[具体内容]

---

## 处理原则

1. [原则1]
2. [原则2]
3. [原则3]
```

---

## 质量要求

一个好的方法文件需要满足：

1. **角色清晰**：一句话说清楚"你是谁"
2. **场景明确**：说清楚"什么时候用"
3. **输出结构化**：有明确的输出模板
4. **处理原则**：有可执行的判断标准
5. **示例**（推荐）：有一个脱敏示例

---

## 提交流程

1. Fork 仓库
2. 创建分支：`git checkout -b method/013-your-method-name`
3. 编写方法文件
4. 更新 `insight-engine/SKILL.md` 的方法索引
5. 提交 PR

### PR 模板

```markdown
## 新方法：#013 [方法名]

### 方法定位
[一句话说明]

### 适用场景
[什么时候用这个方法]

### 核心价值
[这个方法能解决什么问题]

### 测试
- [ ] 是否在示例录音上测试过？
- [ ] 输出是否符合质量标准？
- [ ] 是否有脱敏示例？
```

---

## 方法编号规则

- 001-012：核心方法（已内置）
- 013-099：社区贡献方法
- 100+：实验性方法
