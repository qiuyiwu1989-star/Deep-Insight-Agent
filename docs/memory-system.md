# 记忆系统设计原理

## 为什么需要记忆系统？

单次分析的价值有限。真正的洞察来自于**跨时间、跨场景的纵向追踪**：

- 同一个项目的第1次和第10次会议，立场有什么变化？
- 同一个人在不同场景下的表现是否一致？
- 上次承诺的行动项，这次兑现了吗？

记忆系统让 Agent 具备"长期记忆"，能够：
1. **关联历史**：分析前自动搜索相关历史记录
2. **追踪变化**：对比立场演变、行动项兑现
3. **学习纠正**：记住用户的纠正，下次避免同样错误

---

## 用户隔离原则

### 问题

如果多个用户共享同一个记忆系统：
- A用户的分析结果可能被B用户看到
- 不同用户的上下文可能混淆
- 隐私泄露风险

### 解决方案

1. **严格隔离**：每个用户的分析记录独立存储
2. **身份确认**：回溯历史前必须确认用户身份
3. **不预设**：不假设与用户的过往合作
4. **不串引**：不将A用户的内容透露给B用户

### 实现方式

```
memory/
├── users/
│   ├── user-a.md    # 用户A的画像
│   └── user-b.md    # 用户B的画像
├── analyses/
│   ├── user-a/      # 用户A的分析记录
│   └── user-b/      # 用户B的分析记录
```

## 跨录音关联

### 触发条件

- 同一项目的第N次会议
- 同一人物再次出现
- 用户明确要求"对比历史"

### 关联维度

| 维度 | 对比内容 | 价值 |
|------|---------|------|
| 核心议题 | 推进/停滞/倒退/新增 | 看清项目进展 |
| 人物立场 | 强化/软化/漂移 | 看清人心变化 |
| 行动项 | 完成/部分/未做/无提及 | 追踪执行力 |
| 矛盾 | 新增/旧有 | 看清风险演变 |

## 自动学习

### 纠正类型

| 类型 | 示例 | 学习方式 |
|------|------|---------|
| 说话人纠正 | "说话人1不是张三，是李四" | 更新说话人识别逻辑 |
| 方法纠正 | "不需要用问骨，直接出执行清单" | 调整方法选择偏好 |
| 深度纠正 | "分析太浅，没有刺穿表象" | 提高质量标准 |
| 遗漏信号 | "你漏掉了XX的沉默" | 增加沉默信号检测 |

### 纠正记录

```markdown
# YYYY-MM-DD 纠正记录

## 纠正内容
[具体纠正了什么]

## 纠正类型
[说话人纠正/方法纠正/深度纠正/遗漏信号]

## 适用场景
[下次分析时如何应用这个纠正]
```

## 设计权衡

### 记忆深度 vs 响应速度

- **深度记忆**：搜索所有历史记录，注入完整上下文 → 分析更全面，但更慢
- **浅层记忆**：只搜索最近几条记录 → 响应更快，但可能遗漏关键上下文

**当前选择**：快速扫描 ≤3秒，总耗时上限15秒。超过直接跳过。

### 记忆完整性 vs 隐私保护

- **完整记忆**：保存所有分析细节 → 追踪更准确，但隐私风险更高
- **最小记忆**：只保存核心判断 → 隐私更安全，但追踪能力受限

**当前选择**：保存核心判断和行动项，不保存原始录音转写。
